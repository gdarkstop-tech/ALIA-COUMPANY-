**Cautions**
- Any command that resolves the app config for the store app (`eas submit`, `expo config`, CI scripts) must run with `APP_VARIANT=production`, or it resolves the `.dev` identifiers [E2]. Because of the API-URL validation, it also needs `EXPO_PUBLIC_API_URL` set to an `https://` URL.
- The URL check cannot recognise placeholders: `https://api.dressmywound.invalid` passes it. Check the EAS `production` value before every store build.
- `preview-store` builds use the `.staging` ID. On Play that is a **separate app** with its own listing, App-content forms and package registration. On Apple it needs its own App Store Connect record. Store IAP products are tied to one bundle/package ID (an inference in [E2], **to confirm**). The simplest route is to send release candidates through the `production` profile to TestFlight and the Play internal track.
